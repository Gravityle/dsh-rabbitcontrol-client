# RabbitControl 远程桌面（dsh-rabbitcontrol-client）

在 DeepSeek Harness 里打开 RabbitControl 被控端的画面，并把键盘与鼠标回传给对端。解码在浏览器侧用 WebCodecs，不需要额外播放器。

## 安装

```sh
# npm（发布后）
#   让 agent 执行：用 plugin_manager 的 install_bundle 安装 dsh-rabbitcontrol-client
# GitHub：install_bundle 的 target 传 github:<你>/dsh-rabbitcontrol-client
# 本地目录：install_bundle 的 target 传该目录路径
```

包装里自带边车：`bin/rc-bridge`（macOS）与 `bin/rc-bridge-win-x64.exe`（Windows）。`bridgePath` 留空就自动用它们，因此**不需要编译、不需要配路径**。

## 入口

| 入口 | 位置 |
|---|---|
| 左侧面板列表的「远程桌面」图标 | 与「插件」「任务」并列；点开在中央区域显示面板 |
| 快捷键 `⌘J`（Windows/Linux 为 `Ctrl+J`） | 切到同一面板；面板未注册成功时退回右侧标签页 |

## 使用

1. **第一次打开面板会看到「连接 rc-server」设置卡片**：填 rc-server 的 REST 地址（例如 `https://你的服务器:21118`）→ **保存地址** → 用 rc-server 账号**登录**。
   - 地址会写进插件配置（写不进时面板会说明），登录态存进凭据记录，**与「服务器状态」面板共用**；
   - 换服务器会自动清掉旧登录态，需要重新登录；账号首登被要求改密时，面板会提示先去改密。
2. 登录后面板左侧是**我的设备**：**点设备那一行即可连接**（不再需要选直连/中继）——
   - 设备公布了地址 → 先直连，失败自动换下一个地址、再自动改走中继；
   - 设备没有公布地址（例如插件自带的被控端）→ 直接走中继。
3. 面板左侧是**我的设备**（来自 `/api/v1/devices`），每台在线设备两个按钮：

| 按钮 | 走的路 |
|---|---|
| **直连** | 用设备公布的地址列表逐个尝试（tailnet/局域网地址都公布时会依次试） |
| **中继** | 信令登记后先打洞（`RCP2`）；打洞失败、**或打洞连通但一帧未出**，都自动改走中继（`RCR1`，双向 mTLS） |

3. 连上后画面出现在中央舞台；`高级与手动` 折叠区里有手动地址、离线回放、帧率与键鼠开关。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `bridgePath` | 空 | 空 = 用插件自带的边车（按平台选）；也可指定自有路径 |
| `clipPath` | 内置片段 | 只有回放模式用 |
| `serverUrl` | 空 | rc-server 的 REST 地址；**留空（推荐）**时由面板的首次设置卡片填写并写回配置 |
| `insecureTls` | `true` | 接受自签证书 |
| `signalDeviceKey` | `dsh-rabbitcontrol-client` | 信令设备 key；设备被管理端停用后需更换 |
| `signalTransport` | `auto` | `auto` / `p2p` / `relay` |

## 让本机变成「可被控」（不用额外脚本）

面板「高级与手动」里有一个 **「作为被控端」** 开关：勾上之后，插件自己拉起边车把本机登记到 rc-server，别人（任何装了这个插件的 DSH）就能在设备列表里看到它并连接。

- macOS 上默认提供**真实屏幕**（ScreenCaptureKit + VideoToolbox，插件自带的边车已带 `real-capture` 特性）；需要给 DSH 应用授予「屏幕录制」权限。
- 其它平台（含 Windows）目前会给出**可读报错**而不是静默失败——Windows 的采集/编码/注入后端还没实现。
- 设备码与后端标签（如 `sck+videotoolbox`）会显示在开关下面；`hostDeviceKey` 与客户端的 `signalDeviceKey` 分开，避免互相顶掉。

## 两个行为细节

- **重连会自己恢复**：被控端（如 `rc-cli host`）的设计是「accept 一条连接、服务完就退出」，所以断开后立刻重连可能正好落在它重启的空档里——表现为连上但一帧不出、或连接被拒。边车遇到这两种情况会自动**间隔 2 秒重试同一地址一次**，仍失败才交给面板做"换地址 → 中继"的降级。
- **设备显示名自动上报**：被控端上报的 `hostname` 取**宿主机名**（macOS 用「电脑名称」，例如 `mac-mini`），不需要手工设别名；面板优先显示 `alias`，没有就显示 `hostname`。同一台机器跑多个被控端时，可以用角色的后缀区分（例如 `mac-mini · 真桌面`）。

## 前提与限制

- 对端必须是**支持信令的被控端**（`rc-bridge --serve … --signal-*`）或**地址可直达**的被控端（如 macOS 上的 `rc-cli host --listen`）。
- 跨网段且对端位于代理/NAT 之后时，打洞可能"握手成功但媒体不通"；本插件会自动改走中继，所以中继是可靠路径。
- 目前**没有**"先试局域网直连、失败再打洞、再中继"的三级自动降级：直连与中继是两条独立的路，直连失败会自动换地址、再降级到中继。
